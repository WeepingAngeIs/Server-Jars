# Unyielding improvements: implementation and remaining checks

This is a development checklist, not a release or installation instruction. Existing player progress, settings and rank plans must be preserved. The [acceptance index](../docs/UNYIELDING-ACCEPTANCE-INDEX.md) reconciles exact tested sources, JAR hashes and remaining boundaries; older reports retain their historical scopes.

1. **Daily rewards and Lucky Spin.** Missed-day grace and its displayed policy are implemented. Named quest credits use journal identities and reset generations saved with quest progress; recovery never replays a reset. The [recovery checkpoint](../docs/UNYIELDING-REWARD-RECOVERY-RESULTS.md) passed six native server phases across five actual JVM restarts. The [connected-client checkpoint](../docs/UNYIELDING-REWARD-CLIENT-ACCEPTANCE-RESULTS.md) preserves twelve baseline token/UI passes and verifies the undefined-claim-mode fix with five focused cases on `744be...`; its production build passed 69 units. These are separately scoped runs, not one combined matrix on the latest JAR. Generic crate/loot credits remain on the legacy path. RETURNED means the delivery call returned, not an atomically durable inventory/Pokemon receipt; uncertain payouts still require reconciliation.
2. **Homes, warps and party meetings.** Home/warp icon lists, dimensions and cooldowns are implemented; home information is intended to be scoped to its owner and selections invoke existing commands. The [destination checkpoint](../docs/UNYIELDING-DESTINATION-ACCEPTANCE-RESULTS.md) passed five bounded real-client cases on the byte-identical `216de93...` JAR: owner payload/private-home isolation, native selection, repeat cooldown refusal and stale home/warp rows obeying a later disabled feature. No production build or unit suite was repeated. Party meetings are opt-in with a separate permission, current membership, OPAC full access, approved same-dimension destinations and loaded safe-location checks. The [provider/lifecycle checkpoint](../docs/UNYIELDING-PARTY-PROVIDER-ACCEPTANCE-RESULTS.md) passed ten real-client cases and 69 units on `216de93...`, fixing stale membership after one ordered synthetic provider callback. It covers provider deny/exception/grant/revocation, setter reconnect/role changes, disabled-state retention and mounted-caller refusal. Meeting default remains disabled pending actual modpack/rank acceptance; generated test policy is not live policy. See [meeting contract](PARTY-MEETINGS.md).
3. **Tutorial.** Reopening, permission-filtered command entries and a What's New page are implemented. Historical retained evidence covers real connected-player command/rank filtering, dismissal/history state and manual replay. Its reconnect/"restart" history checks invoke lifecycle hooks and SavedData serialization in one process; they do not prove a real server-JVM tutorial restart. Separate TutorialSmoke code contains guide navigation/search/interruption tests; test code alone is not a fresh native PASS. The index records the older source/JAR separately. Existing passing tutorial cases should not be repeated without a specific regression reason.
4. **Party and quest navigation.** Party roster search/paging, quest status filters and an informational pinned party goal are implemented. Rewards remain personal and sharing remains configurable. This implementation entry is not a claim of an exhaustive UI acceptance matrix; confirmation/progress evidence below must not be relabeled as roster/search testing.
5. **Destructive party confirmations.** Disband and ownership transfers require server-side confirmation and revalidation. The [confirmation checkpoint](../docs/UNYIELDING-PARTY-CONFIRMATION-RESULTS.md) passed 27 assembled-JAR native cases with two clients, a real requester reconnect and a saved server restart on `fb8378...`. It covers cancellation, expiration, stale/replayed/competing confirmations, changed authority, successful actions and personal quest/reward preservation. Clearing pending confirmations on logout fixed the reproduced reconnect defect. Full-pack/rank acceptance and exhaustive interleavings remain outside that proof.
6. **Optional vein-mining feedback.** Feedback remains off by default. The earlier [31-case protection checkpoint](../docs/UNYIELDING-VEIN-PROTECTION-RESULTS.md) is preserved. The [follow-up checkpoint](../docs/UNYIELDING-VEIN-ACCEPTANCE-RESULTS.md), source `51c23f468fa2af1510d93834946269298b7c83f6`, passed 69 units, 42 native cases and captured 48 screenshots on `7a0a1cec...`: cold input, normal-hardness Survival hold-to-break, completed durability, bounded OPAC/addon protection and compact feedback beside a populated six-Pokemon party/chat/toasts at 640x480, GUI 2. This does not establish authoritative live rank/claim policy, every HUD layout or the full pack.
7. **Ground cleanup.** The operator screen, item-age grace, category/dimension settings, countdown/warnings and manual preview are implemented. The [cleanup checkpoint](../docs/UNYIELDING-GROUND-ACCEPTANCE-RESULTS.md) passed 17 native multiplayer/merge/reconnect/restart cases across two real-client server phases on `be397...`; its production fix passed 69 units earlier. Native merge/drop/pickup/redrop, scheduled grace, preview authorization, protected categories and saved restart boundaries passed with pinned public item mods. Logout/server-stop preview invalidation fixed the reproduced stale confirmation. Manual clear targets selected vanilla dimensions; full-pack item/event permutations, arbitrary custom dimensions, live policy and old saves remain unverified. Do not enable a separate cleanup datapack with conflicting functions.
8. **Readable durations and config audit.** Some durations accept units/presets. A bounded audit records individual config edits, admin toggles and ground settings; `/configaudit <page>` exposes up to 100 recent entries. Undo allowlists map icon scale, origin flight speed and seven teleport cooldowns, and restores a value only if it still matches the audited edit. Grouped/external changes are not audited. The [config-audit checkpoint](../docs/UNYIELDING-CONFIG-AUDIT-ACCEPTANCE-RESULTS.md) passed eight real-client packet/command cases on the unchanged `216de93...` JAR, covering numeric undo/reverse records, operator authorization, stale/conflicting values, unsupported/no-op blocking, global-latest ordering and audit text minimization. It checks registered memory values, generated TOML values and audit SavedData NBT in one running server; it does not read audit.dat or prove restart/crash/atomic durability. No production build or unit suite was repeated; the 69-unit result remains the earlier meeting-provider build.

Anya's 2026-11-16 firsthand Mawile test reports basic dropped-food pursuit/eating working. Qualification is Spice of Life Onion Diversity >= 8, including exactly 8, rather than hunger. This is a user-observed basic pass, not full-pack/automated feeding certification; do not repeat it without a new regression reason.

Independent jail-free acceptance has no Jail build or certificate prerequisite. The earlier exact-pair Jail certificate stays separate and unchanged; it does not certify a different candidate or authorize deployment. Installed files, live worlds, private data, settings, art and prior artifacts remain untouched. Heavy builds/runtime checks run on GitHub-hosted disposable inputs.

Authoritative live provider/rank/claim policy, full-pack behavior and actual old-save migration need the corresponding authoritative inputs. Physical power-loss behavior and exactly-once delivery across independently saved systems are not established by these bounded checks. See the index for concrete input blockers and remaining public gaps; this checklist is not an instruction to loop through passing cases or test every feature exhaustively.
