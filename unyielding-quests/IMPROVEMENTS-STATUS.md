# Unyielding improvements: implementation and remaining checks

This is a development checklist, not a release or installation instruction. Existing player progress, settings and rank plans must be preserved.

1. Daily rewards have a configurable missed-day grace and a displayed policy. Journaled spin payouts still require reconciliation because Minecraft inventory and Cobblemon storage are not atomic with the journal. Named quest credits use journal identities and reset generations saved with quest progress; recovery never replays a reset. Generic crate/loot credits remain on the legacy path. RETURNED payouts distinguish a successful call from an uncertain attempt, not durable receipt.
2. Homes and warps have an icon list, dimensions and cooldowns; home information is scoped to its owner and selections invoke existing commands. Party meetings now have an opt-in /partymeet command and separate permission, with live OPAC full-access, membership, same-dimension allowlist and loaded safe-destination checks. Default disabled pending actual modpack/rank acceptance; see PARTY-MEETINGS.md.
3. The first-time tutorial is reopenable, filters its command entries by permissions, and includes a What's New page.
4. Party rosters support search and paging, quest search has status filters, and parties can pin an informational goal. Rewards remain personal and sharing remains configurable.
5. Party disband and ownership transfers require server-side confirmation and revalidation. Focused assembled-JAR coverage passed 27 cases with two actual clients, a requester reconnect and a saved server restart: cancellation, expiration, stale/replayed/competing confirmations, changed membership/ownership/permissions, successful actions and personal quest/reward preservation. A reproduced reconnect bug was fixed by clearing the requester's pending confirmation on logout. See [results, limits and candidate hashes](../docs/UNYIELDING-PARTY-CONFIRMATION-RESULTS.md). This changed binary requires coordinated paired Jail certification before deployment; full-pack/rank acceptance and exhaustive interleavings remain unverified.
6. Optional compact vein-mining feedback remains off by default. Focused assembled-JAR verification passed 31 native cases with two real clients, actual OPAC 0.33.0, vanilla spawn/Adventure/Spectator rules, cancellation/item-use denial and display checks. Reproduced late-cancellation, spawn-boundary and connected-tool claim bypasses were fixed. Clear-HUD labels fit at 640×480/GUI 2; startup chat/toast overlap and full-pack HUD/protection acceptance remain open. See [exact revisions, evidence, limits and deployment hold](../docs/UNYIELDING-VEIN-PROTECTION-RESULTS.md). The changed candidate still requires coordinated paired Jail certification before deployment.
7. Some durations accept readable units and presets. A bounded audit covers individual config edits, admin toggles and ground settings, and `/configaudit <page>` shows up to 100 recent entries. Undo supports map icon scale, origin flight speed and seven teleport cooldown settings; it restores the value only when it has not changed since the audited edit. Grouped edits and external changes are not audited.

Ground cleanup has an operator screen, item-age grace, category and dimension settings, countdown, warnings and manual preview. Manual clear covers selected vanilla dimensions, not arbitrary custom-dimension overrides. Do not enable a separate cleanup datapack with conflicting functions. Test real modpack item merging and multiplayer behavior before deployment.

GitHub compilation and isolated smoke tests do not establish physical power-loss behavior, complete modpack compatibility or exactly-once delivery across independently saved systems.
