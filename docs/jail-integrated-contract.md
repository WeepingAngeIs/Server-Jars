# Integrated jail review contract

This is a bounded review implementation. Admissions default to disabled. The new `native-supported-v2` contract has an explicit console opt-in, subject to the complete pinned-runtime and per-player audits described in [the admission scope](jail-admission-scope.md). It is not approval to enable the user's server or a claim that the full modpack is supported. Historical fixture-only contracts remain available for recovery and regression testing. No profile installation or release-number change is part of this work.

The original `human-empty-v1` contract supports an already selected native Human origin at tier zero, no other selected origin/class layer, no active powers/effects or attribute modifiers, no pending selection or unpersisted cooldowns, an existing self-owned unique Human claim, and empty, settled Accessories/Curios physical and cosmetic stores without slot modifiers. The complete loaded third-party runtime must match pinned binary checksums, including embedded libraries proved against pinned parent binaries. Packed ordinary vanilla stacks, their exact original slots, components and nested contents are retained; selected hand, armor and offhand must be empty. This Human adapter never invokes an origin-power lifecycle, replaces an attachment or seizes/releases a claim.

The `native-equipment-luck-v1` expansion admits ordinary supported vanilla hand, armor and offhand equipment and actual Accessories default-provider normal/cosmetic stacks. Physical Curios compatibility aliases are deduplicated against their backing containers. Full components, nested contents, selected hotbar, destination permissions and native layout are checked. Bound equipment, custom accessory providers, accessory component effects, slot modifiers, occupied destinations, unknown attributes and unsettled lifecycle state are refused. Native equipment/accessory callbacks run once after durable intent, with a separate before/after audit of declared attribute deltas and all other observed player effects. Missing effect intents cannot be inferred from an item marker. Interrupted callbacks remain quarantined; explicit recovery only confirms independently saved, matching native effects.

The expanded origin adapter resolves the loaded Human and main layer from actual registries. It supports tier-zero origins with no power or one audited unconditional native Luck attribute power, plus unpowered unrelated layers. It invokes the actual native lifecycle and verifies its entire declared effect before issuing receipts. It preserves current evolution progress and unrelated layer selections, retains the original unique claim and leases only a free Human claim (or preserves a preowned claim). It never steals a claim or rewinds an entire origin attachment. Built-in origins with other powers, higher tiers, dynamic/global grants, conditions, cooldowns and unknown hooks remain unsupported. The hosted fixture loads a real native Luck origin and class through datapack registries; this does not certify every installed origin.

An append-only command plan binds owner, transaction, source digest, prior/jail location, geometry, original Human audit and prior completed receipt. It quarantines the owner before native removal. A separate immutable item snapshot is the only item-transfer authority. Inventory removal, native Human receipts, claims/player saves, assignment saves and position saves are verified independently through actual-file readback and file/directory durability barriers. There is no cross-store atomicity claim. Only verified completed native returns, durable return position and durable assignment removal permit final quarantine release. A saved initialization marker refuses missing-history resets across restart.

`/unjail <player>` routes managed records through that coordinator. Legacy pardon and UUID pardon cannot bypass outstanding or unavailable custody. Unsupported or ambiguous outcomes retain records and restrictions; no automatic replay, blind refund, merge, overwrite or overflow drop occurs. Completed records never authorize another grant, even after their returned inventory is consumed.

Console setup is explicit: `/jailcustody init`, then `/jailintegrated init`. Neither resets existing history. These commands do not enable admissions. `/jailintegrated check <player>` performs a read-only preflight; console `/jailintegrated mode supported` enables only the audited contract. `/jailintegrated mode disabled` refuses new admissions while retaining existing custody protection and recovery. See the scope document for restrictions and evidence status.

Recovery retains the previous `/jailcustody inspect|audit|hold|reattach|review|restore` interface. `/jailcustody confirm <transaction>` only confirms exact already persisted native phases; it cannot insert items or move a player. `/jailcustody recover <transaction>` is an explicitly requested, audited command continuation: it can finish confinement from verified held native receipts, start a not-yet-started no-op Human receipt against the exact saved initial audit, or finish a release whose origin return is already verified. It refuses uncertain started operations. It still requires a subsequent review and restore to clear quarantine. `/jailintegrated cancel <transaction>` is console-only and only cancels an exactly unchanged prepared source, including an already verified cancellation interrupted before metadata completion; it never transfers items.

The separate disposable test mod invokes real registered `/jail` and `/unjail` commands on real players around the unchanged assembled JAR. It checks exact component/nested-content conservation, no ground drops, repeats, cross-player refusal, non-Human/additional-class/tier/equipment refusal, occupied return slots, actual accessory slot changes, administrator permission loss during return, interface loss/reattachment, a genuine player-file write denial, durable boundary faults, actual disconnects/restarts, an actually loaded uncertified dependency and missing command-history refusal. Test hooks require GitHub-hosted execution and the named disposable world and are not a production admission switch.

Expanded escape handling applies only after an accepted movement packet crosses the boundary and bound item/origin custody is durably held, every native item store is empty, and the jail/interface/claim destination still verifies. It first saves containment at the jail, then issues one ordinary damage call behind an append-only attempt record. Invulnerability and damage/death cancellation are respected. Nonzero player experience, active potion/absorption effects, occupied currency wallets, active origin resource state and unknown serialized attachments are refused because those death surfaces have no custody adapter. No tick, login or recovery path replays lethal damage.

Actual native death/respawn retains items in their immutable custody journal. The clone handoff copies only verified jail receipt keys and hotbar selection; it copies no stacks or origin attachment. NeoOrigins owns its native copy-on-death attachment. The replacement must verify empty stores, temporary Human, current claims, native respawn receipt and an alive player save at the safe jail before attempt completion. A saved respawn interrupted before completion can be explicitly confirmed with `/jailcustody recover`. A cancelled or otherwise uncertain started death lacking that proof remains held for review; the implementation does not invent a respawn or refund. Missing/corrupt attempt history also blocks release.

The separate five-phase expanded smoke uses real `/jail` and `/unjail`, equipped native inventory and both accessory channels, actual lifecycle interruptions, offline refusal, real restarts, accepted movement packets and the native client respawn handler. It also checks unsafe destinations, XP refusal, cancellation and repeated attempts. Results and exact commit/run identifiers must accompany this source contract; source descriptions alone are not passing evidence. Custom payload surfaces, general modded equipment/origins, XP custody and general recovery from cancelled death remain outside this contract. Do not enable production admission on the basis of this bounded proof.
