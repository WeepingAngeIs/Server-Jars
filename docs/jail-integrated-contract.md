# Integrated jail review contract

This is a bounded review implementation, not approval to turn on normal server admissions. `/jail` can admit only in the explicitly named GitHub-hosted disposable integration world. All other installations refuse new admissions before changing inventory or origin state. Existing legacy assignments and console recovery remain available. No profile installation or release-number change is part of this work.

The production adapters support an already selected native Human origin at tier zero, no other selected origin/class layer, no active powers/effects or attribute modifiers, no pending selection or unpersisted cooldowns, an existing self-owned unique Human claim, and empty, settled Accessories/Curios physical and cosmetic stores without slot modifiers. The complete loaded third-party runtime must match pinned binary checksums, including embedded libraries proved against pinned parent binaries. Packed ordinary vanilla stacks, their exact original slots, components and nested contents are retained; selected hand, armor and offhand must be empty. Other cases fail closed. This Human adapter never invokes an origin-power lifecycle, replaces an attachment or seizes/releases a claim.

An append-only command plan binds owner, transaction, source digest, prior/jail location, geometry, original Human audit and prior completed receipt. It quarantines the owner before native removal. A separate immutable item snapshot is the only item-transfer authority. Inventory removal, native Human receipts, claims/player saves, assignment saves and position saves are verified independently through actual-file readback and file/directory durability barriers. There is no cross-store atomicity claim. Only verified completed native returns, durable return position and durable assignment removal permit final quarantine release. A saved initialization marker refuses missing-history resets across restart.

`/unjail <player>` routes managed records through that coordinator. Legacy pardon and UUID pardon cannot bypass outstanding or unavailable custody. Unsupported or ambiguous outcomes retain records and restrictions; no automatic replay, blind refund, merge, overwrite or overflow drop occurs. Completed records never authorize another grant, even after their returned inventory is consumed.

Console setup is explicit: `/jailcustody init`, then `/jailintegrated init`. Neither resets existing history. Normal admissions remain disabled outside the hosted fixture.

Recovery retains the previous `/jailcustody inspect|audit|hold|reattach|review|restore` interface. `/jailcustody confirm <transaction>` only confirms exact already persisted native phases; it cannot insert items or move a player. `/jailcustody recover <transaction>` is an explicitly requested, audited command continuation: it can finish confinement from verified held native receipts, start a not-yet-started no-op Human receipt against the exact saved initial audit, or finish a release whose origin return is already verified. It refuses uncertain started operations. It still requires a subsequent review and restore to clear quarantine. `/jailintegrated cancel <transaction>` is console-only and only cancels an exactly unchanged prepared source, including an already verified cancellation interrupted before metadata completion; it never transfers items.

The separate disposable test mod invokes real registered `/jail` and `/unjail` commands on real players around the unchanged assembled JAR. It checks exact component/nested-content conservation, no ground drops, repeats, cross-player refusal, non-Human/additional-class/tier/equipment refusal, occupied return slots, actual accessory slot changes, administrator permission loss during return, interface loss/reattachment, a genuine player-file write denial, durable boundary faults, actual disconnects/restarts, an actually loaded uncertified dependency and missing command-history refusal. Test hooks require GitHub-hosted execution and the named disposable world and are not a production admission switch.

Broader native origin transitions, populated accessory/equipment callbacks, custom payload surfaces and escape/death completion remain outside this contract. Do not enable production admission on the basis of this bounded proof.
